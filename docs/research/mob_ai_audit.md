# Magma live mob-AI fidelity audit

## Verdict

Mob AI is **not solved for the live simulator**. Magma accepts eleven ordinary mob types plus the Ender Dragon, but ordinary mobs share one small direct-steering loop rather than vanilla's prioritized, mutex-aware `EntityAITasks` scheduler. Of the requested special behaviors, only basic melee pursuit, a simplified wander, damage-only passive panic, a simplified creeper fuse/explosion, single-shot skeleton/blaze projectiles, wither-skeleton wither-on-hit, and a three-state custom dragon flight loop exist. Vanilla path navigation is not connected to the live loop. Pig zombies are present in a scenario tape but have no live entity type or AI.

This conclusion does not conflict with tape replay parity. Replay explicitly runs with `mobs=False` because spawn RNG does not match the oracle, and turns recorded entities into render/physics inputs (`verify/trace/replay_tape.py:642-678,844-868`). It therefore verifies rendering and tape-driven interaction, not autonomous mob decisions or trajectories. The standalone `mob_ai_*` kernels are also not the implementation called by the live game.

The pre-existing CPU checks were run without rebuilding and passed:

```
./magma/game/test_mob_live
mob_live: chase z 14.500000 -> 12.691686 y 4.000000
mob_live: wander moved 6.470 mind 31.346
mob_live: PASS

./magma/game/test_dragon_live
dragon_live: PASS melee/death/portal
```

Those are useful regression checks for the current simplified behavior, not vanilla parity tests.

## Pathfinding verdict

**Live magma does not implement or call vanilla `PathNavigateGround`/A* for mobs.** The live loop ray-tests current LOS, aims directly at a target/waypoint, invokes living collision physics, and checks only a single forward block for jump/drop behavior (`M/magma/game/mob_live.c:111-137,269-290,434-446,481-523`). There is no path object, open/closed set, node cost, door flag, water flag, repath-delay model, or stuck detector in that reachable path.

The repository contains two disconnected navigation surfaces:

1. The legacy `pf_*` A* is explicitly described as a hand-rolled, non-faithful 1.11.2 grid search used by isolated `mob_ai_*` and `entities_world` checks (`M/blaze/core/pathfinding.h:1-13`). CPU/CUDA agreement for those kernels is internal consistency only.
2. The newer `pf12_*` is a vanilla-faithful synthetic port of `PathFinder`, `PathHeap`, and `WalkNodeProcessor`, including node classifications/priorities and door/water handling (`M/blaze/core/pathfinding.h:9-13,341-343`; `M/blaze/core/path_node_processor.h:31-74,157-173,379-413`). It has a Java golden. The separate `path_navigate` battery follows already-supplied points on open ground and explicitly omits finding, solids, stuck/repath, and full movement (`M/blaze/core/path_navigate.h:1-27`).

Vanilla dynamically transforms closed/open doors, rails, water/lava, hazards, fences and open/drop nodes (`O/pathfinding/WalkNodeProcessor.java:303-369,388-447`) and exposes break-door, enter-door, swim, and avoid-sun navigation policy (`O/pathfinding/PathNavigateGround.java:275-361`). The C oracle runner performs exact Java-to-CPU line comparison only when a Java golden exists (`M/blaze/oracle/runner.py:41-64,114-138`). `pathfinding12` and `path_navigate` have such goldens; `mob_ai_zombie_astar`, the other `mob_ai_*` cases, and `ender_dragon` do not. Therefore the low-level `pf12` node processor is verified on its synthetic battery, but **live obstacle routing, node weights, door policy, water avoidance, and path following are wholly unverified because the verified pieces are not wired into live mobs**.

## RNG and determinism verdict

Vanilla uses a per-entity `Random`: `Entity` constructs `rand = new Random()` and immediately consumes it for UUID construction (`O/entity/Entity.java:230-247`). AI tasks call the entity's RNG. The world has a separate `World.rand` (`O/world/World.java:95,108`) for world/spawn operations; for example zombie and spider spawn initialization consumes world randomness (`O/entity/monster/EntityZombie.java:502-519`; `O/entity/monster/EntitySpider.java:200-216`). It is not accurate to model vanilla AI as one shared world RNG.

The Malmo oracle makes construction reproducible but retains the per-entity model: `MixinEntityRandom` replaces an entity's generator with `SeedHelper.getRandom("entity")` (`M/java/Minecraft/src/main/java/com/microsoft/Malmo/Mixins/MixinEntityRandom.java:19-29`), and `SeedHelper` derives a new seed from the named allocator and returns a distinct `Random` (`M/java/Minecraft/src/main/java/com/microsoft/Malmo/Utils/SeedHelper.java:43-51,85-96,121-143`). Construction order still matters, as does every RNG consumption after construction.

Magma has no per-mob `java.util.Random` state in `GmMobLive` (`M/magma/game/mob_live.h:11-29`). Wander chooses a fresh stateless hash of world seed, tick and slot (`M/magma/game/mob_live.c:481-495`); natural spawning similarly hashes tick/attempt (`:334-383`). This is deterministic within C but cannot reproduce vanilla's 48-bit cursor, Gaussian cache, per-entity consumption order, or separate world RNG stream.

Per-mob oracle determinism is feasible under the controlled Malmo oracle, but only after C stores the exact 48-bit `java.util.Random` state (and Gaussian cache) for each entity, obtains or reproduces the exact derived seed in construction order, mirrors UUID/setup consumption, and consumes random values in the exact task order. A separate mirrored world RNG is required where spawn/group logic is in scope. It is not feasible to claim exact parity against an uncontrolled ordinary client whose `new Random()` seeds are not captured.

Existing tests sidestep the mismatch in two ways. `test_mob_live.sh`/`test_mob_live.c` use C's deterministic hashes and assert coarse facts such as "moved closer", "moved more than one block", damage, drops, or a timer, not oracle positions or selected tasks (`M/magma/game/test_mob_live.c:21-200`). Tape replay disables C mob simulation and consumes recorded entities (`M/verify/trace/replay_tape.py:642-678,844-868`). Neither approach tests live per-mob RNG parity.

## Ranked test gaps and proposed designs

1. **No live mob-trajectory parity gate.** Add a runner mode that initializes C mobs from a tape's first entity sample, disables recorded-entity injection, replays identical player inputs/world mutations, and compares stable entity IDs at every tick: position, motion, yaw, target ID, active task/phase, attack/fuse timers, health/fire/effects, and projectile events. Report the first divergent field/tick rather than only an aggregate endpoint.
2. **No task scheduler/priority tests.** Build table-driven C unit fixtures around an explicit task scheduler. Inject a finite sequence of RNG outputs and assert exact task start/continue/reset order, mutex preemption, target retention, task speed, and timer values. Start with common `swim > panic/attack > wander > watch/look` and separate target-task priority fixtures. These tests should compare integer state exactly; use bit equality for ported Java float/double values.
3. **No live navigation test.** Use fixed tiny worlds with a wall and gap, one-block ascent, two-block drop, water strip, lava/fire/cactus hazard, open/closed wooden door, iron door, fence, and sun/shade route. Assert the exact `pf12` node sequence first, then the live entity's waypoint index and trajectory. This exposes the present disconnected-pathfinder problem immediately.
4. **No blaze attack-cycle or flight test.** Seed a fixed entity RNG, place the player at squared distances below 4, between 4 and follow range, and outside 48. Assert melee every 20; 60-tick charge; shots at the vanilla burst ticks; 100-tick reset; vertical offset update; Gaussian projectile vectors; and help retaliation. A controlled oracle tape should record blaze state and all spawned projectiles for the same fixture.
5. **No enderman stare/teleport test.** Deterministic fixtures should vary pumpkin, view dot product around the threshold, 5-tick acquire delay, distance below 4 and above 16, water/daylight, and indirect damage. Record teleport attempts and chosen coordinates, including failed collision/liquid attempts, rather than asserting only a final position.
6. **No pig-zombie live test because the type is absent.** Add two pig zombies and verify player damage causes the vanilla anger duration/sound delay and nearby same-class propagation, while an unprovoked player is not targeted. Include the angry speed modifier's add/remove lifecycle and NBT persistence. This should be the first new scenario-mob acceptance test.
7. **No skeleton bow-state test.** Assert approach outside 15, 20 visible ticks before stopping, draw time, normal-difficulty 40 cooldown, LOS loss behavior, and the randomized strafe toggles. Compare exact projectile velocity/inaccuracy samples against the seeded oracle.
8. **No creeper state-machine test.** Tick at 2.99, between 3 and 7, beyond 7, and behind an LOS blocker. Assert swell task continuation, positive/negative state, fuse rollback, explosion tick 30, and ocelot preemption.
